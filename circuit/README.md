# Submitted monitoring hardware

The website's Download .circ button serves `volcano-demo.circ` as **volcano.circ**. This standalone project opens directly in classic Logisim 2.7.1 and Logisim-evolution 4.1.0. Its three circuits are MonitorGUI, MonitorAux and WindowCounters, copied without logic changes from the full hardware project. The generator follows actual subcircuit references; it does not maintain a second hand-written warning implementation.

The full `volcano.circ` remains the backend's Evolution 4.1.0 project, including MonitorCore and ReplayHarness. Its RAM ports are version-specific and are deliberately excluded from the manual download. Both files are generated by `scripts/build_monitor.py` and packaged with the source.

## Manual demonstration

1. Open the downloaded file; MonitorGUI is selected. Choose the hand/poke tool in the native toolbar.
2. In classic Logisim, input pins start at zero and show binary. Set mask to **1111** (decimal 15) for all sensors connected. With V,T,G,A at zero, NORMAL turns on. Evolution additionally restores the saved defaults20,20,20,20 and mask15.
3. Set V to **01000111** (71): WATCH. Set T to **00111101** (61) as well: DANGER / EMERGENCY. G and A are independent inputs; their strict thresholds are65 and70. Threshold values are labelled in decimal, although classic constants also display hexadecimal.
4. Set sample_enable to1. Set clk to0 then1 to commit exactly one reading. Repeated high clock values do not count again. Counters complete a window after ten edges. Pulse reset to clear the counters.
5. Clear one mask bit to demonstrate FAULT: effective flags and emergency turn off. Values above100 also produce FAULT. Restore all mask bits to reconnect.

Changing input pins updates combinational warnings immediately. Only the enabled rising clock edge updates native counters. The website separately commits slider drafts through its replay job; the downloaded editor is an independent manual demonstration.

## Verification

`make check-circuit` checks both generated projects. `make check-rules` rejects wrong thresholds, interfaces and malformed custom-port geometry. `make test-download` executes all43 fixed truth/threshold/fault cases and two635-tick full-GUI counter scenarios, including600 commits, boundary faults, hold, reset and restart, in pinned Evolution.

For an installed classic JAR, with a working X display:

```sh
DISPLAY=:97 python3 -B -m scripts.check_download --classic-jar /usr/share/logisim/logisim.jar
```

`:97` was the isolated QA display, not a required user display number. Normal desktop users can use their existing DISPLAY. This optional check fails if classic is unavailable; it never substitutes browser/Python results. `--project path/to/downloaded-volcano.circ` tests the actual saved download.

`scripts/java/CheckCircuitImport.java` is a separate optional native loader gate, compiled against each tested JAR. It treats loader diagnostics as failures and checks every component, custom-port coordinate and physical pin binding. [Compatibility evidence](../reports/circuit-compatibility/verification.md) includes actual classic GUI screenshots and before/after import results.

The full backend checks remain `make test-combinational`, `make test-counters`, `make test-replay` and `make test-native`. The separate bridge-proof.circ remains the fixed four-row Stage2 experiment; its schema differs from the full replay protocol. See [core](../docs/monitor-core.md), [counter timing](../docs/window-counters.md), [replay](../docs/replay-harness.md) and [output schema](output-schema.json).

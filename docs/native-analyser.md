# Standalone native analyser

Build with `make build-asm`, then run `build/monitor < assembly-input.bin`. The executable is x86-64 Linux, GNU AT&T assembly, PIE with a non-executable stack. It reads only stdin and writes tagged output to stdout. The header and records are exactly the version1 little-endian contract in spec/protocol.md. It validates the entire bounded input, including trailing bytes, before printing success output. Exit0 means success,2 means malformed input,3 means an I/O failure. Stderr identifies failures; a successful run has empty stderr.

Classification, validity, counter updates, minima/maxima, 64-bit sums, valid counts and averages are all implemented in assembly/monitor.s. Invalid whole records are excluded from all sensor statistics. Counters include faults in the ten-sample clock and preserve C+d before clearing current totals. The current, last valid and worst valid warnings remain distinct in returned data. Zero valid records use S_EMPTY and NO_VALID_DATA without division. Averages use unsigned RDX:RAX division with high half zero and floor(sum*100/count); REPORT AVERAGE prints two decimal places, while S contains integer average_x100. REPORT STATUS contains the worst valid severity or NO_VALID_DATA.

Main preserves RBX,RBP,R12–R15, uses RIP-relative addresses and aligns every libc call. The extra printf argument is passed in a16-byte stack reservation. Leaf classification and counter-packing helpers use only caller-saved registers. No POPCNT CPU extension is required.

backend/app/asm_parser.py validates the complete tagged grammar, row order/input echoes, per-sensor order, numeric bounds, summary consistency, report lines and footer. It decodes statistics returned by the executable; it does not calculate replacement statistics. `make test-native` runs twelve canonical scenarios, compares every returned bus with actual Logisim and independent expected snapshots/statistics, and rejects eleven malformed binary streams. A separate actual /dev/full test confirmed output failure produces exit3. Parser regressions cover missing/duplicate/reordered records, truncated/extra output and inconsistent statistics/reporting.

reports/stage6/ stores native stdout/stderr, decoded examples and verification inventory for empty, all-fault and required two-reading statistics cases. The full job provenance/source/executable hash boundary is completed by Stage7.
